PROJECT INDEX / PUBLIC WORK

Small tools for questions I keep coming back to.

Each project has a narrow problem, a working implementation, and a limitation worth stating. The apps use synthetic data and do not connect to private systems. Hosted demos are pending GitHub Pages activation; use the setup links to run them locally.

01 / CASH FLOW WORKSPACE

Browser application

Randwise

A monthly cash-flow planner for recording income and expenses, understanding category totals and keeping a portable record.

ToolsHTML · CSS · JavaScript
PersistenceBrowser localStorage
DataUser-entered or synthetic
Run locally ↗Source files ↗

The problem

Raw transactions are difficult to reason about without a month, type and category view.

What is implemented

Create, edit and delete entries; filter and search; review income, expenses, net position and category totals; export visible rows as CSV.

Boundary

No bank connection, financial account, server or financial advice. Records are stored in the current browser.

02 / INCIDENT REVIEW

Browser application

Incident Atlas

A focused incident log for practising response coordination, recording impact and keeping follow-up notes attached to an event.

ToolsHTML · CSS · JavaScript
WorkflowOpen → resolved → review
DataSynthetic examples or your own
Run locally ↗Source files ↗

The problem

Incident notes lose value when severity, impact, status and response are scattered across separate places.

What is implemented

Severity and status filters, searchable records, resolve/reopen actions, response notes, summary metrics and JSON export.

Boundary

This is not live monitoring, paging, on-call management or an incident system of record. Use synthetic data; no confidential details.

03 / ARCHITECTURE RECORDS

Browser application

Decision Archive

A lightweight ADR workspace for preserving context, selected options and the trade-offs behind technical decisions.

ToolsHTML · CSS · JavaScript
RecordsContext · rationale · consequences
PortabilityMarkdown and JSON
Run locally ↗Source files ↗

The problem

A decision without its context and alternatives is difficult to revisit when requirements change.

What is implemented

Create and maintain records with status, tags, search and filters; export Markdown and back up or restore validated JSON.

Boundary

No sign-in, team collaboration, access control or shared storage. Records stay in this browser unless exported.
