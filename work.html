Each project begins with a specific question. The point is not to display a stack of technologies, but to make a behaviour, decision or limitation easy to inspect.

01 / API

RuleTrace

A .NET validation API with a separate browser example using invented records.

C#.NET 10xUnit
Open browser example ↗ API source Architecture notes

THE QUESTION

Can a validation result explain which rule was evaluated and why an invented record failed or passed?

What is implemented

The source contains a .NET minimal API, deterministic validation rules, health and validation routes, and xUnit test source. The browser example is a separate client-side demonstration; it does not call a hosted version of the API.

EVIDENCE

Rule evaluation, explicit outcomes, API routes and test source in the repository.

BOUNDARY

The API runs locally. It is not hosted and does not implement authentication or persistence.

Next checks: confirm test results in CI, add endpoint-level integration tests and make malformed-request responses more explicit.

02 / DASHBOARD

ReleaseLens

A TypeScript dashboard for exploring synthetic build and deployment history.

TypeScriptHTMLCSS
Open dashboard ↗ Source files

THE QUESTION

Can build outcomes, failure categories and run details be explored without connecting to a real CI provider?

What is implemented

The dashboard supports search, filters, derived metrics, run details and browser-side CSV export. Its dataset is invented to make the interaction repeatable and safe to share.

EVIDENCE

Filtering, summary calculations, run-detail views and CSV export in the frontend.

BOUNDARY

The dashboard does not connect to GitHub Actions or another CI provider. The data is sample data.

Next checks: add focused tests for filters, derived metrics and CSV escaping.

03 / LOCAL APP

Randwise

A local-first cash-flow planner for income, expenses and monthly summaries.

JavaScriptLocal storageCSV
Open live demo ↗ Source repository Setup and boundaries

THE QUESTION

Can a small budgeting tool make a month's income, outgoing and spending categories easier to understand?

What is implemented

Users can add, edit and delete transactions, search and filter by month/type/category, review summary metrics and export the visible rows as CSV.

EVIDENCE

Transaction editing, filtering, derived totals, category summaries and CSV export.

BOUNDARY

No bank connection, server, account system or financial advice. Records stay in the current browser.

04 / PRACTICE TOOL

Incident Atlas

A local incident review log for severity, impact, response and follow-up notes.

JavaScriptSearch/filterJSON
Open live demo ↗ Source repository Setup and boundaries

THE QUESTION

Can a review log keep incident status and response notes connected so that follow-up is not lost?

What is implemented

Create, edit and delete incidents, change state, search and filter by severity/state, review summary metrics and export data as JSON.

EVIDENCE

Incident lifecycle actions, filters, response fields and resolution summaries.

BOUNDARY

This is not a monitoring agent, pager, alert router or shared incident system. Use synthetic data only.

05 / DECISIONS

Decision Archive

A small Architecture Decision Record workspace for preserving rationale and trade-offs.

JavaScriptMarkdownJSON
Open live demo ↗ Source repository Setup and boundaries

THE QUESTION

Can a technical decision still make sense later, when its context, alternatives and consequences are easy to find?

What is implemented

Create and edit decision records, track status and tags, search and filter entries, export Markdown and back up or restore JSON with basic record validation.

EVIDENCE

Decision lifecycle, search, Markdown export and JSON backup/restore.

BOUNDARY

No sign-in, team collaboration, access control or cloud sync. Records remain local unless exported.
